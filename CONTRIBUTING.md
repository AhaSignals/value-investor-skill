# Contributing

Useful contributions include a minimal failing input, a calculation counterexample, a missing source-time boundary, or a clearer explanation of a model limit.

1. Use fictional or properly licensed, redacted fixtures.
2. Include expected behavior and why it follows from the research contract.
3. Add a focused test for the observable behavior.
4. Run the tests and public-identity check in the README.
5. Explain whether English/Chinese documentation or the input contract changes.

Do not submit private holdings, account information, credentials, raw licensed data, profitability promises, fabricated calibrated probabilities or celebrity impersonation prompts. A rejected/withheld result can be correct behavior.

New sector models need a specific research contract and appropriate evidence; a generic prompt alone does not establish model coverage. Keep additional API integrations optional. The offline demo must remain usable without paid services.
